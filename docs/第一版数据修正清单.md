## 一、22 条「标签标了、连锁产物没写」的形态转换（`cards_v21.json` · transitions）

规则表命中一张卡时，产物是从**这张卡自己的 `transitions`** 里按
「触发标签 + 层数类别」取的。标签标了、产物没写 → 规则命中却不变形，
玩起来像这张卡是死的。下面 22 条逐条补上（`trigger` 与正文/规则表口径一致）：

| # | 卡 | 补的 trigger | result |
|---|---|---|---|
| 1 | 冰 | `遇热 + 热` | 水 |
| 2 | 铜 | `遇热 + 热` | 熔融铜 |
| 3 | 铁 | `遇热 + 热` | 熔融铁 |
| 4 | 固态汞 | `遇热 + 热` | 汞 |
| 5 | 沙 | `遇热 + 热` | 熔融玻璃 |
| 6 | 熔融铜 | `液体 + 热` | 铜蒸气 |
| 7 | 熔融铁 | `液体 + 热` | 铁蒸气 |
| 8 | 熔融金 | `液体 + 热` | 无变化（黄金没有气态形态） |
| 9 | 熔融玻璃 | `液体 + 热` | 无变化（玻璃没有气态形态） |
| 10 | 铜蒸气 | `可熔 + 热` | 熔融铜 |
| 11 | 铜蒸气 | `遇酸 + 酸` | 铜溶液 |
| 12 | 铁蒸气 | `可熔 + 热` | 熔融铁 |
| 13 | 铁蒸气 | `遇酸 + 酸` | 铁溶液 |
| 14 | 汞蒸气 | `可熔 + 热` | 汞 |
| 15 | 汞蒸气 | `遇酸 + 酸` | 无变化（卡表没有汞溶液） |
| 16 | 铜溶液 | `遇酸 + 酸` | 无变化（已经是溶液） |
| 17 | 铁溶液 | `遇酸 + 酸` | 无变化（已经是溶液） |
| 18 | 黄金 | `遇酸 + 酸` | 无变化（带惰性标签，不溶于酸） |
| 19 | 汞 | `遇酸 + 酸` | 无变化（卡表没有汞溶液） |
| 20 | 固态汞 | `遇酸 + 酸` | 无变化（卡表没有汞溶液） |
| 21 | 硫磺液 | `可溶 + 酸` | 无变化（卡表没有硫磺溶液） |
| 22 | 熔融铜 | `遇酸 + 酸` | 铜溶液 |

补充说明（写数据时的口径，策划请过一眼）：

- **序号 8/9/15/16/17/18/19/20/21 这 9 条的 result 是「无变化（原因）」**：
  意思是"规则命中了，但结果就是不变形"。解析器现在把这种写法读成
  **声明的无变化**（`TransitionRule.declaredNoChange`），规则表命中后按
  「仅改属性 / 无变化」处理 —— 规则自带的改属性（例：酸规则1 的 **H-2**）照常生效。
  括号里的原因会原样进日志，方便对照。
- **序号 6/7（熔融铜/熔融铁 → 蒸气）与序号 10/12/14（蒸气 → 熔融）互为逆反应**，
  两边都写上，冷热来回推的时候形态能双向走。
- **序号 2/3（铜、铁的「遇热 + 热」）与已有的「可熔 + 热」产物一致**：
  热规则 4（遇热）优先级高于热规则 5（金属→熔融），所以热≥2 时走的是 4；
  两条产物相同，命中哪条结果都一样。
- **铜溶液 / 铁溶液去掉了 `金属` 标签**（它们仍是"溶液"：判定靠卡名后缀 + 液体形态）：
  留着 `金属` 会让酸规则 1（金属→溶液）先截获，而这两张卡本来就是溶液，
  再变一次溶液没有意义 —— 去掉后走酸规则 5 的「遇酸 → 无变化」，
  "已经是溶液了不再变形"这条语义才成立。

## 五、3 副 v2.1 牌组（`game_config.json` · decks）

**这是"规则为什么不执行"的主因**：原来的三副牌组用的是旧 `game_config` 的食材
（秘银锭 / 卤水 / 石英砂…），那些卡在 v2.1 卡表里没有形态、标签、形态转换，
规则表对它们一条都命中不了。**旧牌组一副没删**，追加三副：

| id | 名字 | initialBladeId | ingredientIds |
|---|---|---|---|
| `deck_water_v21` | 水 · 冷热流 | `water` | water, ice, steam, salt |
| `deck_iron_v21` | 铁 · 熔融流 | `iron` | iron, molten_iron, iron_solution, iron_vapor |
| `deck_sulfur_v21` | 硫 · 酸蚀流 | `sulfur` | sulfur, sulfur_gas, sulfur_liquid, sulfur_powder |

配套代码改动（两个文件都在 `Scripts/Prototype/`，同层，不违反分层）：

- **`GameConfig.ResolveIngredient(id)`**：解析 `ingredientIds` 时，
  旧 `ingredients` 表里没有的 id **回退到 `CardSpecs.Material(id)`**。
  不回退的话这 12 个 id 全部查不到、被静默跳过 —— 牌组看起来配好了、
  实际手牌少几张，正是"规则不执行"最像的一种故障。查不到时打 warning，不静默丢。

  ★ **回退时以 v2.1 卡表的那一份为准（实机跑出来的第二个坑）**：
  `water` / `sulfur` / `alien_alloy` 这几个 id **两张表里都有**，
  而 `CardSpecs.EnsureRegistered()` 的合并策略是"同 id 保留旧数值"，
  于是 v2.1 牌组拿到的「水」带着**旧配置**的 H=1（盐性列），而 `cards_v21.json` 里写的是 H=2。
  刀片 H = 核心卡的 H → 玩家拿「水」当核心，**刀片 H=1，启动一次就爆刀、关卡当场结束**，
  自动试玩日志里就是"分数 8 → 立刻 LevelEnd"，规则再对也来不及跑。
  所以回退分支改为按卡表重建一份：`h/d/v` 取卡表字段，描述字段也取卡表那份，
  并把 H/D/V 同步进 attrs（卡面属性区读的是 attrs，不同步会显示旧配置的 1/9/1）。
  旧牌组走的是第一条分支（图鉴里有），**一个字节都没变**。
- **`GameConfig.Build` 末尾调一次 `CardSpecs.EnsureRegistered()`**（幂等）。
  放在最后的原因：它做的是**合并**（同 id 保留旧数值、只补 v2.1 的描述字段），
  倒过来先注册会把旧数值冲掉。旧流程的数值一个都没改。

## 六、v2.1 专用目标分（HUD 的 `x / y`）

**问题**：HUD 显示 `总分 x / 1000`，那个 1000 来自 `levels[].targetScore`（旧模型数值）。
v2.1 每次启动只有「目标素材 V + 刀片 V」（V 档位 1~8），一关 4 回合 × 5 次行动
= 最多 20 次启动 → 撑死一两百分，**永远达不到 1000**，关卡只会"4 回合耗尽"结束，
玩家会觉得"规则没生效"。

改动：

- **`TableSettings.V21TargetScore = 60`**（新常量）。
  正文 §2.6 只说"达到目标分即胜利"、**没给数值** → 60 是让第一版能收关的**占位数**，待策划定。
  60 ≈ 一关里正常打完十几次启动的得分（按平均每次 4~6 分估）。
- **`TableRulesV21.BeginLevel` 用这个值**（不再用传进来的 `levelTargetScore`），
  并且会打一行日志说明"配置里旧流程的 targetScore 不参与 v2.1 结算"。
  HUD 的 `x / y`、榨汁机液面、**达标判定**读的都是同一个 `targetScore`，所以一起变。
- **`GameConfig` / `level.TargetScore` / 旧流程一行没动**：切回旧流程仍然是 1000/1500/2000。
- **达标收关已接通**：`TurnRules.TargetScore` 在 `BeginLevel` 里就被填成 60，
  `TurnEngine.Finish()` 每次结算检查 `score >= TargetScore` → `state.levelOver = true`，
  日志写「★ 达到目标分 60（当前 N）→ 关卡结束」，`TableTurnLoop` 随即把阶段切到 `LevelEnd`。
  （这条链路是原有实现，本轮只是把 1000 换成 60，让它第一次真的可能被触发。）
