# 把 v2.1 规则引擎接进 3D 桌面（整合说明）

> 一页说清：**哪个钩子挂在哪、旧流程怎么保留、还有哪些没接。**
> 相关文档：`docs/规则引擎架构.md`（规则内核怎么搭的）、`docs/卡牌规则_v2.1_飞书原文.md`（正文，以它为准）
> 代码：`Assets/Scripts/Table/`　离线自测：`Tools/RuleProbe/run.ps1`

---

## 一、一句话

**`TableTurnLoop` 还是那个阶段机（现在该谁操作），但它不再算任何规则 ——
规则与状态全部落到新增的 `TableRulesV21`（刀片 / 桌面素材 / 手牌法术 / 分数 / 行动机会 / 回合），
每一次结算都调已经离线验证过的 `TurnEngine`。旧流程一行没删，靠 `TableSettings.UseRulesV21` 分流。**

```
   3D 桌面（表现）              TableTurnLoop（阶段机）           TableRulesV21（规则与状态）        TurnEngine（规则内核）
   ───────────────             ──────────────────────           ────────────────────────          ──────────────────────
   PlayCard / JuicerRig   ←──  phase / staged / notice     ←──   blade / table / hand        ←──  StartBlade / PlaySpell
   TableInteraction       ──→  Confirm / ActivateJuicer    ──→   score / actionPoints            EndTurn / EndLevelByChoice
   TableHud（IMGUI）      ←──  只读字段                    ←──   DescribeHud / lastLog      ←──  全过程中文日志
```

依赖是**单向**的：规则侧从不读 `TablePhase`，也不知道 3D 卡长什么样。
所以把 `TableRulesV21` + `Scripts/Rules/` 搬去 2D 棋盘或纯文字原型，规则一行都不用改。

## 二、钩子表：v2.1 的每一步挂在哪

| 正文要求 | 挂在哪 | 一句话说明 |
|---|---|---|
| 模式开关（默认 v2.1） | `TableSettings.UseRulesV21` | 关掉 = 旧流程；HUD 上显示当前模式，设置面板里能切（只对下一关生效） |
| 每关 4 回合 × 每回合 5 次行动 | `TableRulesV21.turnIndex / actionPoints`（常量取 `Rules.LevelRun.TurnsPerLevel / ActionPointsPerTurn`） | 回合开始 `actionPoints = 5`；只有"启动破壁机"扣 1 |
| 初始手牌 4 素材 + 1 法术 | `TableRulesV21.BeginLevel → DealInitialHand` | 牌组决定用哪 4+1 张，不够就从 `cards_v21.json` 按顺序补足 |
| 玩家选 1 张素材当刀片核心 | `TableTurnLoop.ConfirmBladePick → ChooseCore` | 点手牌素材 = 选候选（`PickCoreCandidate`），确认才成立；该卡移出手牌 |
| 出牌（素材上桌） | `TableTurnLoop.Confirm → ConfirmV21 → TableRulesV21.PlayMaterial` | **不消耗行动机会**；上桌后自动选中当启动目标（HUD 标明"自动选中"） |
| 法术附魔到刀片 | `TableInteraction.HandleLeftClick → TableRulesV21.OnSpellCardClicked → TurnEngine.PlaySpell` | 点手牌法术即打出，**不消耗行动机会**；层数与冷热覆盖都在引擎里 |
| 启动破壁机 | `TableHud 顶栏按钮 → TableTurnLoop.ActivateJuicer → TableRulesV21.TryActivate → TurnEngine.StartBlade` | 消耗 1 行动机会 + 1 刀片 H；结算顺序整条在引擎里 |
| 启动要有目标素材 | `TableRulesV21.selected`（点桌面素材选中，`TableInteraction` 转发） | 没选中就拒绝启动并提示"先在桌面上点一张素材" |
| 3D 反馈：冲压 + 灌罐子 | `TableRulesV21.PlayActivateFeedback → JuicerRig.PlayStamp() / SetScore(总分, 目标分)` | 目标素材被移走时走 `PlayCard.ConsumeInto` 飞进罐口 |
| 回合结束附魔 −1、桌面保留 | `TableTurnLoop.EndRoundOrLevel → TableRulesV21.EndRound → TurnEngine.EndTurn` | 衰减只掉"会衰退"那份；桌面素材一张不动 |
| 关卡结束四条件 | `TableRulesV21.levelOver / bursted / endReason` | 4 回合耗尽 / 爆刀 / 主动结束 / 达到目标分；爆刀走 `phase = LevelEnd` |
| HUD 状态区 | `TableHud.DrawTurnPanelV21` | 模式、回合 x/4、行动机会 x/5、总分/目标分、刀片 H&V、四种附魔层数、本回合启动次数、目标素材 |
| 未识别规则警示 + 查看入口 | `TableHud.DrawRulesWarning` / `DrawRulesReportPanel`（**F2**） | 报告建不出来时报"报告没建出来"，绝不假装干净 |

### 3D 卡 ↔ 规则状态的对应关系

| 规则对象 | 3D 外壳 | 怎么找回来 |
|---|---|---|
| `MaterialState`（桌面素材） | `TableMaterialCard`（挂在 `PlayCard` 上） | `TableRulesV21.FindTable(PlayCard)` |
| `SpellCard`（手牌法术） | `TableSpellCard` | `TableRulesV21.FindSpell(PlayCard)` |
| `MaterialCard`（手牌素材） | 无（靠卡面显示名 `名字 D3`） | `TableRulesV21.FindHandMaterial(显示名)` |

> 手牌 3D 卡是"照着手牌列表逐张造出来"的，除了名字没有别的稳定锚点。
> 手牌素材的显示名带 D（`水 D3`），这样运行时 D 变了卡面名字也跟着变 ——
> 因为 3D 卡面是造卡那一刻烤死的，改 data 不会让贴图变（见 `CardFactory` 顶部说明）。

## 三、旧流程怎么保留的

**一个开关 + 若干处 if，旧代码一行没删。**

```
TableSettings.UseRulesV21 (本分支默认 true)
   │
   ├─ TableTurnLoop.V21  →  { UseRulesV21 && rulesV21 != null }
   │
   ├─ StartLevelWith()      v2.1：setup.ClearHand + rulesV21.BeginLevel；旧：setup.RebuildHand
   ├─ BuildBladeCard()      v2.1：摆"候选核心"；旧：Card.Of(turn.blade)
   ├─ ConfirmBladePick()    v2.1：ChooseCore + StartFirstTurn；旧：记 SelectionLog → Select
   ├─ Stage()               v2.1：不拦行动次数（出牌不消耗行动机会）；旧：拦 ActionsLeft
   ├─ Confirm()             v2.1：ConfirmV21（出牌）；旧：整段原样
   ├─ NextTurn()            v2.1：回合 / 结束判定；旧：turn.NextTurn + LayoutHand
   ├─ Update()              v2.1：直接 return（没有杯内粒子模拟）；旧：整段原样
   ├─ SyncJuicer()          v2.1：推 rulesV21.score；旧：推 turn.score
   ├─ TableSetup.DealHand() v2.1：直接 return（手牌由 rulesV21.RebuildHand 全权负责）；旧：原样
   ├─ TableInteraction      v2.1：左键点桌面素材/法术；旧：只有拖动
   └─ TableHud              v2.1：DrawTurnPanelV21 / DrawTurnResultV21 / DrawLevelEnd/Result 的 v2.1 分支 / F2 报告
                            旧：DrawTurnPanel / DrawTurnResult / DrawLevelEnd / DrawLevelResult 原样
```

**切换方式（两种都行）**

1. 运行时：`Esc → 设置 → 规则模式` 点一下按钮（面板里会提示"退出关卡重进才生效"）。
2. 改代码：`TableSettings.UseRulesV21 = false`（`ResetToDefault()` 会把它改回 `true`）。

**为什么不支持中途热切换**：两套玩法的状态完全不通用（v2.1 是 `BladeState` + 桌面 `MaterialState`，
旧流程是 `TurnState` + 杯内粒子 + `activeEffects`）。打到一半换引擎只会留下一桌半套脏状态。
所以开关只对**下一关 / 重开本关**生效 —— 这比"能热切但状态对不上"安全得多。

## 四、这次对引擎 / 正文做的假设与改动

### 4.1 没有改任何引擎代码

`Assets/Scripts/Rules/**` 一行未动。整合全部通过公开接口完成：
`TurnEngine.StartBlade / PlaySpell / EndTurn / BeginTurn / EndLevelByChoice`、
`LevelRun`、`BladeState`、`MaterialState`、`LayerLedger`、`RuleReport.BuildAll`。
**不需要新增任何 public 接口。**

### 4.2 假设（都写进代码注释了）

| # | 假设 | 在哪 | 为什么这么定 |
|---|---|---|---|
| 1 | **初始 4 素材 + 1 法术从"玩家选的牌组"里取**，不够才从卡表补 | `DealInitialHand` | 正文只说"初始手牌 4 素材 + 1 法术"，没提牌组。这样"三选一牌组"在 v2.1 里仍然有意义，且换牌组 = 换一套开局，不用第二份配置 |
| 2 | **H/D/V 三级来源：v2.1 卡表 → 旧 game_config → 占位表** | `ApplyValues` | ★ 这条是实跑踩出来的：牌组里的卡（秘银锭 / 卤水 / 硝石 / 硫磺）**不在 cards_v21.json 里**，只有旧 `game_config.json` 那套数值。早期版本跳过旧配置直接用占位表，于是它们全变成 H=1 —— 刀片 H 只有 1，一进关卡启动一次就爆刀，4 回合的关卡根本走不完。三级来源的顺序和"这张卡是几号来源"都记在 `MaterialCard.source` 上，HUD 会照着说 |
| 3 | **素材的 D 默认 3** | `DefaultMaterialD` | `MaterialState.D` 有默认值但正文没有这个数；卡表 `d` / 旧配置 `d` 优先 |
| 4 | **目标分兜底 30** | `FallbackTargetScore` | `LevelData.targetScore` 为 0 时 JuicerRig 液面会算成 NaN，而且"达到目标分即胜利"会变成一开局就胜利。本关配置是 1000，所以实际走的是 1000 |
| 5 | **"本回合最后一次启动"的判定** | `IsLastStartForSure()` | 正文说"最后一次不一定是第 5 次"，所以不做次数判断：**行动机会用完 / 手牌空了 / 已达标**这三种情况才算确定是最后一次，其余每次启动都传 `isLastStart = false`。玩家点"结束本回合"时那一次不是启动，所以不会漏掉吞噬 |
| 6 | **法术点一下即打出** | `HandleLeftClick` | 正文说"法术打出无代价、不消耗行动机会"，且法术没有桌面落点。所以单击而不是拖拽；同时保留"拖进法术槽 + 按放置"这条老习惯也能走通（同一个入口）。**开局准备阶段禁止打法术** —— 那时候刀片核心都还没定 |
| 7 | **出牌自动选中新素材当启动目标** | `PlayMaterial` | 正文要求启动要选目标。自动选中省一次点击，但 HUD 必须写明"自动选中"，点别的素材可换 |
| 8 | **卡表/旧配置都没数值时的占位值与 H 下限** | `ApplyValues` + `TableSettings.UsePlaceholderCardValues` | 两套配置都没给数值的卡，H 会兜到 `PlaceholderMinH = 12`。**这不是平衡性数字，是"能开局"的下限**：刀片 H = 核心卡 H，H=0 就是一进关卡爆刀。用没用到占位值会记进 `placeholderCards` 并在 HUD 上列名 |
| 9 | **H/D/V 与 attrs 两套口径不混用** | `ApplyValues` 末尾 | `Ingredient.h/d/v` 是 v2.1 的 H/D/V；`attrs`（盐性/汞性/硫性）是旧玩法的。规则一律读 `h/d/v`；同步一份到 attrs **只为了卡面能显示**（`CardFactory` 的属性版式读 attrs） |
| 10 | **刀片核心的默认候选 = 牌组指定的 initialBladeId** | `CoreCandidate()` | 正文没有这条规则（核心由玩家选）。但当玩家什么都不点时，"配置里本来就想让它当刀片的那张"（如"硫硝爆燃"→外星合金）比"列表第一张"合理。旧流程里这个字段是开局刀片，v2.1 里降级成默认候选 |
| 11 | **3D 卡与规则状态用引用绑定，不靠名字** | `PlayCard.bindingMaterial / bindingSpell` | ★ 也踩到了：卡面名字里带着 D（`水 D3`），而 D 会变 —— 靠名字找回手牌那张卡，D 一变就失配，表现是**点"放置到桌面"没反应、牌还留在手里**。现在造卡时就把引用绑上去 |

### 4.3 已知的表现层将就（不是规则问题）

- **法术卡面的副标题前缀写着"【变速模块】"**。原因是 `Card` 只有"素材 / 模块"两种 kind，
  加第三种要动 `Card` 的 switch、`CardFactory` 的版面、以及每一处 `IsModule` 判断（约 20 个文件）。
  v2.1 模式下法术不走旧流程（不投杯子、不并 `activeEffects`），只需要"能被看见、能被点"，
  所以先用现成容器装上，玩法完全由 `TableRulesV21` 接管。
  卡面标题里已经把需求原文写出来了。
- **手牌素材的 D 与数值来源写在卡名里**（`水 D9` / `硝石 D4（旧配置V=0）`）。
  规范做法是给 `CardFactory` 加一条"运行时角标"通道。
- **卡面属性区的三个数用的是旧 attrs 版式**（H 盐性 / D 汞性 / V 硫性）。
  数值本身已按 v2.1 的 H/D/V 同步过去了，但版式文字还是旧玩法的 —— 版式跟着 kind 走，
  要改就得动 `CardFactory`。

## 五、还没接的部分（**这些现在不会生效，别以为已经能用**）

| # | 没接的东西 | 正文出处 | 现状 |
|---|---|---|---|
| 1 | **法术的"直接得分"类**（结晶） | §2.1 三类法术 | 引擎会解析 `根据当前刀片冷层数直接加分` 并执行；但"每层算几分"正文没给，走 `TurnRules.ScorePerLayerDefault = 1`。**没验证过实际手感** |
| 2 | **"影响素材"类法术** | §2.1 | 引擎侧只有"作用于刀片"的实现路径；作用于桌面素材的写法（`影响素材法术`）目前没有卡表样本，未验证 |
| 3 | **复制法术**（法术卷轴献祭："指定手牌中的1张法术卡，复制2张"） | 卡表 `spell_scroll.sacrifice` | 需要"指向手牌里某一张"的交互，规则文本解析不出选择动作 → 进未识别清单（F2 可查） |
| 4 | **随机法术卡**（法术卷轴 D 耗尽） | 卡表 `spell_scroll.exhaust` | 引擎有 `ProduceRandomSpell`（固定种子 `TurnRules.RandomSeed`），产出会进手牌；但"随机"这件事没有 UI 反馈 |
| 5 | **卡牌自身的「启动」文本** | 卡表 `startup` 字段 | **v3 正文没有这一步**（形态变化全由附魔规则表驱动），`TurnRules.ApplyCardStartupText` 默认 `false`。所以 `水` 的"消耗所有热层数额外产生水蒸气"这类写法**不会生效** —— F2 报告里列在"v3 已取消的写法" |
| 6 | **「不消耗刀片H」类写法** | 旧卡表 | v3 改成启动固定扣 1 H，没有豁免机制。引擎遇到这类写法会打警告并跳过（`superseded` 一节，F2 可查） |
| 7 | **粉末形态**（酸≥2 且固体 H 归零 → 变粉末） | 规则表 D-3 | 卡表 `transitions` 里没有指向粉末的条目 → 只扣 H、无法变形。`RuleReport.tableGaps` 会列出来（F2 可查） |
| 8 | **爆炸规则**（热≥1 且粉末且易燃） | 规则表 B-2 | 优先级被 B-1（易燃）先截获，按字面实现永远不可达 —— 属于正文自相矛盾，已列在 `EnchantRules.Conflicts()` |
| 9 | **存档 / 读档** | §九 | 没有做。`TableRulesV21` 的状态是纯内存对象，很容易序列化，但没接 |
| 10 | **空白卡的分组显示** | §2.1（"需单独统计数量"） | 引擎会产出空白卡（实测：D 耗尽产出了 3 张）、`TableRulesV21.blankCount` 也在数，但 3D 桌上它就是一张普通卡，HUD 还没单列这个计数 |
| 11 | **刀片的 3D 表现只到"摆一张卡"** | —— | `JuicerRig` 已经能冲压出刀片模型，但每次启动都重播一遍完整冲压动画，没有"按 H 变化调整刀片外观"这类表现 |
| 12 | **本关的牌组卡不在 v2.1 卡表里** | —— | 牌组用的还是旧 `game_config.json` 的素材（秘银锭 / 卤水 / 明矾 / 醋酸 / 硝石…），它们**不在 `cards_v21.json` 里、没有 tags 与 transitions** —— 所以附魔规则表对它们基本无从下手（结算日志里 `硝石（）` 那个空括号就是"没有形态与标签"）。要真正跑通形态变化，牌组得改用 v2.1 卡表里的素材 |

### 实跑时那一版卡表报告的原始数字（`DSH_TURNPROBE=1`）

```
[V21] 卡表解析报告：素材 31 张 · 法术 8 张 ｜ 句子 155 条：已解析 150 · 未识别 5
      执行不了 0 · 占位数值 4 · 可疑产出 1 · 规则表接不上 22 · v3 已失效写法 8
```

HUD 上那一行写的就是这个"未识别 5"，按 F2 能把它们逐句列出来（哪张卡 / 哪个字段 / 原句 / 原因 / 建议）。
**"规则表接不上 22" 也一并列在 F2 里** —— 那是"卡表标了标签但没写连锁产物"，
表现是"规则命中了却不变形"，同样属于"看起来生效其实没生效"，所以不能只报 5 条。

> 第 1~8 条里凡是**解析不出来**的，都会在 F2 的"未识别清单"里逐句列出（哪张卡 / 哪个字段 / 原句 / 原因 / 建议）。
> 这是这套架构最重要的一条约定：**要么能跑，要么明说不能跑 —— 绝不能让没实现的规则看起来生效了。**

## 六、怎么验

```powershell
# ① 编译（0 error / 0 warning）
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\dsh-compile-check.ps1"

# ② 规则内核的离线断言（必须全绿）
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tools/RuleProbe/run.ps1

# ③ 端到端自动试玩（不用手点）
$env:DSH_AUTOPLAY=1; $env:DSH_PLAYCAPTURE=1
$env:DSH_CAPTURE_DIR="$env:TEMP\v21-play"; $env:DSH_TURNPROBE=1
& "D:\unity\2022.3.62f3c1\Editor\Unity.exe" `
  -logFile "$env:TEMP\v21-play.log" `
  -projectPath "C:\Users\yu_cr\Desktop\taptapgamejam2026\UnityProject" `
  -executeMethod GameJam.EditorTools.AutoPlayHarness.Run
```

> **★ 命令行两个坑（都踩过，写在这里省得再踩）**
> 1. `-executeMethod` 必须指向一个**方法**：`GameJam.EditorTools.AutoPlayHarness.Run`。
>    直接写类名会报 `executeMethod class 'EditorTools' could not be found` 然后**退出码 1 直接结束**，
>    日志里只有这一行，看起来像"Unity 什么都没干"。
> 2. **不要加 `-quit`**：它会在 `-executeMethod` 返回后立刻退出，
>    而"进 Play → 跑探针"是靠 `EditorApplication.update` 一帧一帧推的 ——
>    加了 `-quit` 就一帧都跑不到。收尾由探针自己 `EditorApplication.Exit(0)` 负责。
> 3. **不要加 `-batchmode`**：它能跑（有 GPU 上下文），但 `ScreenCapture` 在这个组合下会丢图。
>    正常窗口模式跑最稳。

`DSH_TURNPROBE=1` 时，`AutoPlayHarness` 会按 `TableSettings.UseRulesV21` 自动选一条探针：

- `true` → **v2.1 探针**（stage 40~69）：开场 → 选关 → 选牌组 → 选刀片核心 → 确认 →
  出牌（验证行动机会不掉）→ **打法术**（验证附魔层数加上去、行动机会不掉）→
  启动破壁机（验证行动机会 −1、刀片 H −1、分数增加）→
  结束回合（验证行动机会重置、附魔 −1、桌面保留）→ 一路推到关卡结束。
- `false` → 旧流程探针（stage 19~30），一行没动。
